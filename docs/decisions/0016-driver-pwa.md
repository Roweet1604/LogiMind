# 0016: Driver PWA (P9)

Date: 4 Nov 2026. Status: accepted (decided unattended by Claude Code).

## Decision
- **Separate app** in `driver/`: React + Vite + Tailwind + `vite-plugin-pwa`, dev port 5174, proxying `/api` to the backend. It has no router and no map library, and uses the same colour tokens as the console. It is mobile-first: buttons are at least 52 px high, with large text.
- **Installable.** The manifest (`driver/pwa.manifest.js`) is standalone, starts at `/`, and has 192/512 px icons, including a maskable one. The icons are plain PNGs generated by a script, not artwork. A Workbox service worker precaches the app shell so the app opens without a connection. `/api` is not cached by the service worker.
- **Token handling:** the token is read from `#t=...`, stored in `localStorage`, and removed from the address bar. It is kept so the installed app, which opens at `/` without the fragment, still knows its route. It is short-lived (at most 24 h) and covers one route only.
- **Offline stop list:** the app saves the last stop list per link in `localStorage` and shows it with "Offline copy saved at ..." when the API cannot be reached.
- **Queued reports:**
  - Delivered/failed reports go into a per-link queue first. Each report has a `client_event_id` made when the driver tapped the button.
  - The queue is sent in order on start-up, on the browser's `online` event, every 20 s while anything is queued, and with "Sync now".
  - Reports are kept on no connection, 401, 408, 429 or 5xx; they are dropped (and the driver is told why) on 404, 409 or 422.
  - The server de-duplicates by `client_event_id`, so a resend cannot double-count.
  - The 20 s retry was added after the real-browser check: with the server down but the phone's network up, no `online` event fires.
- **Photos need a connection.** The file input is disabled offline, so there is no photo queue (the cut line allows this). Before upload, the app re-encodes the photo to JPEG through a canvas, at most 1600 px on the long side. This keeps it under the 3 MB limit and drops EXIF/GPS data where the browser supports it. If that fails, it sends the original and the server's limits apply.
- **Navigation:** a link to `https://www.google.com/maps/dir/?api=1&destination=<lat>,<lon>` opens the phone's installed maps app (Android/iOS) or the browser. It needs no key and LogiMind sends nothing to it. Only lon/lat plans get the link; planar instances show "No map".
- **Expired or revoked link:** the app says so, and says how many reports on the phone were not sent.
- **Replanned plan:** the app shows "This route was replanned", using `superseded_by`.
- **Ops console:** a "Drivers" panel on feasible plans creates and revokes a link per route (the URL is shown once) and shows the latest report per stop.

## Not done
- No offline photo queue. No push to the driver when the plan changes; the driver sees `superseded_by` on the next load.
- In production the PWA must be served over HTTPS (service workers need a secure context; `localhost` is exempt). The backend's CORS must include the driver origin, or `/api` must be served from the same origin.
