# 0010: Webhooks, rate limiting and audit log in the API (P6d)

Date: 4 Nov 2026. Status: accepted (decided unattended by Claude Code).

## Decision
- **Webhook endpoints** (tables `webhooks`, `webhook_deliveries`, migration 0002): `POST /api/webhooks` {url, events}, `GET /api/webhooks`, `DELETE /api/webhooks/{id}` (deactivates the endpoint and keeps its history), `GET /api/webhooks/{id}/deliveries`. Events: `plan.completed`, `plan.failed`, `plan.replanned`. All of these need an API key and are tenant-scoped.
- **Signing secret**: `whsec_` + 32 random bytes. It is returned once at creation and never listed again. It is stored in plaintext in the database, because the server needs it to sign (unlike API keys, it cannot be hashed). It is tenant data, never a repository secret.
- **Delivery** runs on a separate 2-thread pool (`app/services/notify.py`), never on the solver thread, so retries cannot delay or skew solver timing. The HTTP adapter is `HttpxSender`; tests use `FakeSender`, so everything runs offline. There are up to 4 attempts with 1/2/4 s back-off, retried on network errors, 429 and 5xx; other 4xx answers are final. Each delivery series is stored with its attempts, last status and errors, and gets an audit row `webhook.delivered` / `webhook.failed`. The payload holds plan id, state, solver status, validator verdict and engine, but no routes.
- **SSRF guard (basic)**: only http(s) URLs. `localhost` and literal loopback/private/link-local/reserved IPs are refused unless `LOGIMIND_WEBHOOK_ALLOW_PRIVATE=1`, which is dev-only and off by default. **Known limit:** host names are not resolved, so a public name that resolves to a private address is not caught. Resolve-and-check (or an egress proxy) is needed before a public deployment.
- **Rate limiting**: one token bucket per API key, checked in `require_principal` after authentication. Requests without a valid key get 401 before the limiter. Over the limit, the answer is 429 with `Retry-After`. Defaults are 60/min with a burst of 20 (`LOGIMIND_RATE_PER_MIN`, `LOGIMIND_RATE_BURST`). It runs in process only and is not shared between workers. The test suite raises the limit in `conftest.py` because the tests poll plans; the limiter has its own small-limit tests.
- **Audit log**: `GET /api/audit?limit=` returns the tenant's log, newest first (max 1000). Rows are written for plan create/complete/fail, order import, webhook create/deactivate and webhook delivery.
